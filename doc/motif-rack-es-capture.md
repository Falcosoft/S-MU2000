# MOTIF-RACK ES: 実機から取るものの段取り

ファームウェアに手を入れずに、実機から取れるものを取る段取り。使うのは取扱説明書に載っている口だけ
（パネルのバルクダンプ、ダンプ要求、プログラムチェンジ、ふつうの演奏）。
[motif-rack-es.md](motif-rack-es.md) の静的な読みの答え合わせと、足りない Data（音色）の穴埋めが目当て。

**まだ何も実機へ送っていない。** ここに書いた手順は計画で、数字（かかる時間など）は見積もり。

> 取ったバルクダンプと録音は配らないこと（中身はヤマハの音色と波形）。`roms/motif-rack-es/` に置けば git には入らない。

## やってはいけないこと

* **検査モードの T12（MIDI では `A0 0C 00`）は Factory Set。ユーザーのデータが全部消える。** 検査モードには、先に控えを取るまで入らない
* 取扱説明書と Data List に載っていない SysEx は送らない
* 更新の受け付け状態（[EXIT]・[PAGE>]・[MUTE/SEL/ENTER] を押しながら電源）には入らない

## 0. 用意するもの

| | 状態 |
|---|---|
| **Data List（PDF）** | **まだ手元に無い。** バルクダンプの番地とバイト数の表、エレメントのパラメーターの並びが要る。ヤマハのサイトで配っている |
| MIDI の線 | RACK ES の MIDI IN / OUT ↔ パソコンの MIDI の口（DIN）。**どの口を使うかは未確認**（RACK ES の USB-MIDI のドライバは古く、今の Windows で動くか分からない） |
| デジタルの音の線 | RACK ES の OPTICAL OUT → Babyface の光入力。44.1kHz・24bit |
| 送る道具 | `build/midisend.exe`（MIDI ファイルを流す）、`build/rec.exe --send`（録りながら流す） |
| 受ける道具 | SysEx をファイルに落とせるもの（MIDI-OX など）。`tools/dump/recv_dump.py` は MU2000 専用なので、そのままでは使えない |
| 確かめる道具 | `tools/motif/mr_bulk.py check`（チェックサムと長さ）、`mr_wavenames.py`（波形の名前の一覧） |

Babyface の設定は MU2000 の録音と同じ（44,100Hz。クロックは RACK ES の光入力に合わせる）。録音は `rec.exe --float` で。

## 1. 控えを取る（最初に必ず）

パネルから全部のユーザーのデータをバルクダンプして、ファイルに落とす。こちらからは何も送らない。

1. 受ける道具を、SysEx を全部ファイルへ落とす状態にしておく
2. RACK ES の UTILITY からバルクダンプを実行する（操作は取扱説明書のとおり）
3. `python tools/motif/mr_bulk.py check 控え.syx` で、全部のメッセージが OK になることを確かめる
4. **もう 1 回取って、2 つのファイルが同じ中身かを比べる**（途中で欠けていないかの確認）

これがそのまま、何かあったときに戻すための控えになる。戻すときは同じファイルを実機へ流す。

## 2. プリセットの音色を取る

Data List が来てから。手順は 2 通りあり、Data List を見てから選ぶ。

* **プリセットを番地で直接要求できる場合**: 音色ごとにダンプ要求（`F0 43 2n 7F 00 ah am al F7`）を送り、返ってきたバルクを保存する
* **「今の音色」しか要求できない場合**: バンクセレクトとプログラムチェンジで音色を選び、「今の音色」をダンプ要求する。これを全音色ぶん回す

どちらも 1 音色ずつ「送る → 返事を待つ → チェックサムを確かめる → 保存」。返事が無い・チェックサムが合わないときは、同じ音色をやり直す。
要求のバイト列は `mr_bulk.py request ah am al` で作れる。

取れたら、音色ごとに次を表にする（Data List のパラメーターの並びで読む）。

| 取り出すもの | 使い道 |
|---|---|
| エレメントごとの波形番号、鍵の範囲、ベロシティの範囲 | 録音の計画（どの波形を、どの鍵で録るか） |
| エレメントの音量、EG の時間と高さ、フィルター、LFO | 静的な読みで出した換算の式の答え合わせ |
| リバーブ・コーラスへの送り | 「送りの 4 本」のどれが何かの決め手 |

## 3. 基準の録音（短い。静的な読みの答え合わせ）

デジタル出力で録る。1 本あたり数秒から十数秒。**どの録音も 2 回ずつ録って、同じになるかを見る**（同じなら出力は決まった値で、あとの比べが楽になる）。

雛形の音色を 1 つ作っておく: エレメント 1 つ、フィルターは通すだけ、EG は平ら、LFO・エフェクト・EQ は切る、パンは中央。
波形は 1 周期が分かりやすいもの（波形の名前の表の `Sine`）。

| 録るもの | 確かめたいこと | 読みでの予想 |
|---|---|---|
| 無音（何も鳴らさない） | デジタル出力の底。0 が並ぶか | ― |
| エレメントの音量 127 と 64 | 音量の目盛り | **12dB の差**（高さの表は音量が半分で 0x20、チップは 0x10 = 6dB、という読み） |
| リバーブへの送りを 127 と 64（エフェクトは切ったまま、送りだけ変える）| 送りの目盛り | 6dB の差。ただし音として出てこなければ、別のやり方に変える |
| 1 オクターブ上と下の鍵 | 音程の目盛り | 周波数がちょうど 2 倍・半分 |
| アタックの時間を 0・32・64・96・127 | EG の速さの目盛り | 8 目盛りで時間が半分。いちばん遅い値が約 19.8 秒なら、表の単位はサンプル数 |
| 和音（8 音を同時に） | 発音をずらす仕組み | 立ち上がりが最大 3 つの時刻に分かれる |

予想と違ったら、違ったほうが正しい。文書と骨組み（`src/motif/swp50.h`）を直す。

## 4. 波形の録音（長い。試しを 1 本やってから決める）

1. **試し**: 波形を 1 本だけ選び、雛形の音色で全部の鍵（128）を 1 秒ずつ鳴らして録る。約 3 分
2. 録ったものから、**鍵ごとにサンプルが切り替わる境目**が見つかるかを確かめる（隣の鍵と、音程を合わせたうえで波形の形を比べる）
3. 境目が見つかれば、区間ごとに真ん中の鍵で長く録る（ループが何周も入る長さ）
4. 2 と 3 の手間と時間を測ってから、全部の波形（1,859 本）をやるかを決める

全部を「全鍵 × 8 秒」で録ると約 22 日ぶん。境目を先に見つけてから録れば数日の桁、という見積もり。
プリセットが実際に使っている波形と鍵の範囲（2 で取った表）から先に録ると、早く役に立つ。

## 5. 記録の付け方

* 取ったファイルは `roms/motif-rack-es/capture/` に、日付と中身が分かる名前で置く
* 録音ごとに、送った MIDI ファイルを同じ名前で残す（あとで同じ条件をエミュレーターへ流せるように）
* 予想と結果は、この文書の 3 の表に列を足して書き込む
