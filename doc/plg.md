# PLG ボード（プラグインボード）を載せるための調査メモ

狙いは PLG150-VL（VL 音源。オーナーの手元にあるのは 150 のほう）を S-MU2000 の中で鳴らすこと。
2026-10-02 時点の調査。
まだ音は出ない。何が揃っていて何が足りないかの記録。

## 本体とボードのつながり

| | 中身 |
|---|---|
| シリアル | 0xF00000 の SCI4 のチャンネル 3。3 スロットを 1 本の口で切り替える（0x20 番地の `targets`。下位 4bit が送り先、上位 4bit が受け元） |
| 速さ | 分周 0x10 → 8MHz / 16 / 16 = 31,250bps。中身は MIDI そのもの |
| 音（本体 → ボード） | スレーブ SWP30 の出力 18・19（`melo(14)`・`melo(15)`） |
| 音（ボード → 本体） | スレーブ SWP30 の入力 10・11（スロット 1）、12・13（2）、14・15（3） |

配線は MAME の `ymmu2000.cpp` による。

## スロットの受け口（`src/plg.h`）

ボードは `plg_board` を継いで作り、`mu2000::plug(スロット, ボード)` で挿す。

| | |
|---|---|
| `rx(byte)` | 本体が 1 バイト送り終えたところで呼ばれる（`targets` がそのスロットを向いているときだけ） |
| `tx(byte)` | ボードが本体へ 1 バイト返す。受け元の切り替えがそのスロットを向いていなければ捨てられる |
| `run_sample(in, out)` | 1/44100 秒進める。音の行きと帰り |

シリアルは**線の上げ下げではなくバイト単位**で渡す。本体とボードは別の時計で動くので、
ビットの幅を合わせるより確かに届く（`sci4_device::set_plg_tx` / `plg_rx`）。
ボードの中身は状態の保存（`state.h`）にまだ入れていない。

確かめる道具は `build/plgtest`（`src/plgtest.cpp`）。聞くだけのボードを挿して起動し、
届いた SysEx と液晶の移り変わりを出す。`--reply` で要求への返事、`--hold` で電源を入れるときに
押しておくボタンを指定できる。

```bash
make build/plgtest.exe
build/plgtest.exe <rom ディレクトリ> --slot 1
```

## 起動時に本体がスロットへ送るもの

`SMU2000_SCI4_TRACE=1` を付けて動かすと、SCI4 から出て行くバイトが stderr に出る
（`src/mame/machine/sci4.cpp` の `tx_start`）。

```bash
SMU2000_SCI4_TRACE=1 build/boot.exe <rom ディレクトリ> 400000000 2> sci4.txt
```

ボードが 1 枚も無い状態で出てきた順:

| 送り先 | メッセージ | 読み |
|---|---|---|
| 全スロット（targets=07） | `F0 43 10 4E 00 10 02 01 F7` | モデル ID 4E（プラグインのシステム）へのパラメータ変更 |
| スロット 1（targets=11） | `F0 43 30 4E 01 10 00 F7` | ダンプ要求。ボードはここで自分が何者かを返すはず |
| スロット 2（targets=22） | 同上 | |
| スロット 3（targets=44） | 同上 | |
| 全スロット | `F0 43 10 4E 00 10 02 01 F7` | もう一度 |
| 全スロット | `F0 43 10 4C 00 00 7E 00 F7` | XG System On |
| 全スロット | `F0 43 00 4C ...`（多数） | XG のバルク。各パートの設定を丸ごと渡している |

つまり**ボードの認識は MIDI の SysEx（モデル ID 4E）のやり取り**で、その後は本体が
受けた設定を XG のバルクでボードへ流している。

## VL の板（`src/plg_vl.h`）

H8/3002（`src/mame/cpu/h8/`、MAME から移したもの）に ROM・RAM・DSPV を繋いだ板。
ROM のファイルを渡して挿す。バイトの並び（16bit ごとの上下）は、リセットベクタが読めるほうを自動で選ぶ。

```bash
make build/plgtest.exe
build/plgtest.exe <rom ディレクトリ> --vl <VL の ROM> --dspv dspv.txt
```

| | 状態 |
|---|---|
| CPU と内蔵周辺 | 動く。手書きのプログラムで確かめた（`build/h8test`）。実物の ROM ではまだ |
| 本体とのシリアル | 動く。`h8test --write-rom` が出す試験用の ROM（受けたバイトに 1 足して返す）を載せると、本体の送った SysEx が +1 されて戻る |
| DSPV | **音は出ない**。レジスタの読み書きを受けて、送り込まれたプログラム（64bit × 256 語 × 2 面）とデータを覚えるだけ。`--dspv` で読み書きを書き出せる |
| IC06（XS992A0） | 入れていない。役目が分からない |
| 状態の保存 | まだ |

実物の ROM が来たら最初に見るもの: 起動して本体の ID の要求に答えるか（`Checking PLG` を越えるか）、
未定義の命令が出ないか、DSPV へ何を書くか。DSPV へのプログラムの転送が取れれば、命令の解読に入れる。

## ボードの名乗り方

本体の 0x0C20D2（名前）、0x0C2258（ID）、0x0C2186（版）から読んだ。
要求の雛形は 0x1BBA2D から並んでいる。返事の 3 バイト目は 0x10 でなければならない。

| | 本体 → ボード | ボード → 本体 |
|---|---|---|
| 名前 | `F0 43 30 4E 01 00 00 F7` | `F0 43 10 4E 01 00 00` + 14 文字 + `F7` |
| ID | `F0 43 30 4E 01 10 00 F7` | `F0 43 10 4E 01 10 00` + 3 バイト + `F7` |
| 版 | `F0 43 10 18 5A 00 F7` | 1 バイト読み捨て、続く 3 バイトを数字として `V?.??` に入れる（頭の形は未確認） |

名前は RAM の 0x41D73C（スロットごとに 14 バイト）、ID は 0x41D775（3 バイトずつ）、
版は 0x41D766（5 バイトずつ、既定は `V0.30`）に入る。名前の頭 2 文字が空白なら「ボード無し」。
普通の起動では ID だけを聞き、名前と版は下の 2 つのモードでだけ聞く。
VL が ID に何を返すかはまだ分からない（ボードの ROM の中にある）。

名前の返事は `plgtest` で確かめた。聞くだけのボードに `PLG150-VL` と返させると、
下の PLG DOWNLOAD MODE の画面にその名前が出る。

## 電源を入れるときのボタンで入るモード

0x11A512 が、電源を入れた直後に押されているボタンを見て振り分ける。
（[Drum]+[PLAY]+[VALUE+] の本体のダウンロードモードは別で、ダウンローダの側が見ている）

| 押しておくボタン | 入るもの |
|---|---|
| [EXIT] | `2000 EX Revision1` の表示 |
| [PLAY]+[MUTE/SOLO] | 検査モード（RAM・カード・A/D などの検査。`MAIN PROGRAM` と `PLUGIN SLOT1-3` の版も出る） |
| [Piano]+[Chrom.Perc.]+[Organ] | 検査モードの別の入り方（0x43E8D0 を立てる。版の表示を繰り返す） |
| [EXIT]+[SAMPLING/MODE] | 0x11A5A8（未調査） |
| **[AUDITION]+[SELECT]+[Synth pad]** | **PLG DOWNLOAD MODE** |

## PLG DOWNLOAD MODE（0x11AB98、ループは 0x11AE64）

`plgtest --hold "audition,select,synthpad"` でエミュ上でも入れる。順に:

1. `PLG DOWNLOAD MODE / Ver1.00 99-OCT-05` を出す
2. `Checking PLG`。3 スロットに名前・ID・版を聞く
3. ボードが 0 枚なら `NO PLG ERROR!`、2 枚以上なら `TOO MANY PLG ERR!`。**ちょうど 1 枚**のとき、その名前を出す
4. `HostSelect=...` を出して、ホスト（PC）の口とボードの間を素通しにする
5. あとは、ホストから来るバイトとボードから来るバイトの両方を眺めて、
   XG の Display Letter（`F0 43 10 4C 06 00 00` + 文字 + `F7`）が流れたら液晶に出すだけ

つまり本体は**橋渡しをするだけ**で、書き込みの手順そのものは PC 側のソフトと
ボード側のプログラムが持っている。PLG150 系はファームウェアを書き換えられる作りで、
そのための入口と読める（PLG100 系はマスク ROM）。

ここから言えること:

* ボードに「書く」口があるなら、PC からボードへ任意のバイト列を届ける道は本体に元からある
* ただしボードが受け付ける命令（読み出しがあるか、どんな形か）は**ボードの ROM を読まないと分からない**。
  ヤマハが PLG150 用の更新データを配っていた形跡は見つけていないので、命令の見本も無い
* 読まずに書くと元の中身を失う。**このモードから何かを書き込むのは、ROM を別の手段で読んでからにする**

## PLG150-VL の基板（写真から。2026-10-02）

オークションの出品写真（同じ型の別の個体）で刻印を読んだ。基板の型番は XY239。

| 位置 | 刻印 | 読み |
|---|---|---|
| IC02 | H8/3002 HD6413002F16 | CPU。X01 = 10.000MHz |
| IC03 | 44 ピン SOP、ラベル「©1999 YAMAHA XY261B0」 | プログラム ROM。ラベルで元の型番は見えない。ラベル貼りなので書き込み済みの品（フラッシュか OTP）で、マスク ROM ではない |
| IC04, IC05 | CY62256LL-70SNC × 2 | SRAM 32KB × 2 = 64KB（0x200000-0x20FFFF と合う） |
| IC08 | YSS217B-F | DSPV。X02 = 22.5792MHz |
| IC09 | EliteMT LP621024DM-70LL | SRAM 128KB。DSPV の隣で、DSPV 用のメモリと見られる |
| IC06 | YAMAHA XS992A0 | 44 ピン QFP のゲートアレイ。役目は未確認（MAME の PLG100-VL の定義には出てこない） |
| IC07 | 9248 ほか | 小さいロジック。未確認 |
| CN02 と周りの「A」の区画 | 部品なし | アナログ回路の跡。使われていない |

ラベルの無い別の個体の写真で、IC03 は **富士通 MBM29F800BA-70**（8Mbit、5V、ボトムブートのフラッシュ、44 ピン SOP）と読めた。
ヤマハの刻印は「©2002 YAMAHA」で始まる別の版らしい（ラベルの個体は ©1999 の XY261B0）。**ROM の版は 1 つではない。**
電池は載っていないので、設定を覚える先もこのフラッシュ。本体の PLG DOWNLOAD MODE とも話が合う。

### PLG100-VL の基板との比べ（写真、基板の型番 XT416）

部品の並びも位置の番号も PLG150-VL と同じ。違いは IC03 だけに見える。

| 位置 | PLG100-VL | PLG150-VL |
|---|---|---|
| IC03 | 「©1997 YAMAHA XT47810 / M538002E-D9」。OKI MSM538002E、8Mbit のマスク ROM（44 ピン SOP）。MAME の `xt47810.ic03`（1MB）と合う | ラベル「©1999 YAMAHA XY261B0」 |
| IC04, IC05 | SRM2B256SLMX70（32KB × 2） | CY62256LL（同じ大きさ） |
| IC09 | HM628128BLFP-7（128KB） | LP621024DM（同じ大きさ） |
| IC06 | YAMAHA XS992A0 | 同じ |
| IC08 | YSS217B-F | 同じ |

つまり **150 は 100 の ROM を載せ替えたもの**で、回路は同じと見てよい。MAME の PLG100-VL の
番地の割り振り（ROM 0x000000、RAM 0x200000、DSPV 0x400000）がそのまま使えるはず。
IC06（XS992A0）は 100 にもあるので、MAME の定義が省いているだけ。

## IC03 を基板に載せたまま読めるか（データシートで調べた分。2026-10-02）

**理屈の上では読める。ただし実物でテスターを当てて確かめることが 3 つある。**

H8 の側（H8/3048B のハードウェアマニュアル REJ09B0325 の付録 D と 20.5 節。H8/3002 そのものの
マニュアルではないが、同じ H8/300H 系列で、モード 1-4 の話は共通のはず）:

| H8 の状態 | アドレス | データ | AS・RD・HWR・LWR |
|---|---|---|---|
| リセット（RES = L） | **L を出し続ける** | 切り離し | H を出す |
| ハードウェアスタンバイ（STBY = L） | 切り離し | 切り離し | 切り離し |

* **リセットを押さえるだけでは読めない。** H8 がアドレスを全部 L に引っ張っているので、ライターとぶつかる
* **スタンバイなら全ピンが切り離される。** 入れ方は「先に RES を L、それから STBY を L」。
  戻すときは STBY を H、発振が落ち着くのを待って RES を H

フラッシュの側（MBM29F800BA のデータシート、44 ピン SOP）:

```
 1 RY/BY   2 A18   3 A17   4 A7    5 A6    6 A5    7 A4    8 A3    9 A2   10 A1   11 A0
12 CE     13 VSS  14 OE   15 DQ0  16 DQ8  17 DQ1  18 DQ9  19 DQ2  20 DQ10 21 DQ3  22 DQ11
23 VCC    24 DQ4  25 DQ12 26 DQ5  27 DQ13 28 DQ6  29 DQ14 30 DQ7  31 DQ15/A-1
32 VSS    33 BYTE 34 A16  35 A15  36 A14  37 A13  38 A12  39 A11  40 A10  41 A9   42 A8
43 WE     44 RESET
```

実物で確かめること:

1. **H8 の STBY ピンが VCC に直結されていないか。** 抵抗を介さずに繋がっていたら L に落とせない（この道は使えない）
2. **フラッシュの RESET（44 番）が基板のリセット線に繋がっていないか。** 繋がっていると、H8 を止めるために
   RES を L にした時点でフラッシュもリセットされ、出力が切り離されて読めない
3. **ほかの部品がバスに出てこないか。** SRAM（IC04・IC05）、DSPV、ゲートアレイ（IC06）の選択線は、
   H8 が切り離されると宙に浮く。プルアップ（基板に並んでいる 47kΩ の抵抗アレイ）で H に保たれていれば黙っているが、
   どの線に付いているかは回路図が無いと分からない

電源も問題になる。クリップで VCC を当てると基板全体（H8、DSPV、SRAM）に給電することになり、
ライターの電流の上限を越えるかもしれない。越えるなら外から 5V を入れて GND を共通にする。

外して読む場合は、これらの心配が全部無くなる。

## PLG100-VL の中身（MAME の `plg100-vl.cpp` より。150 は未登録）

|---|---|
| CPU | H8/3002、10MHz。SCI1 が本体とのシリアル |
| 音源 | DSPV（YSS217-F）、22.5792MHz。0x400000-0x40007F |

## 何が足りないか

1. **ボードの ROM。** 手元に無い。更新プログラムのような配布物も無い。
   H8/3002 は ROM を内蔵しないので、中身は基板上の IC03 にある
2. **H8/3002 の CPU。** MAME にある（`src/devices/cpu/h8/`）。SH-2 と同じやり方で移せる
3. **DSPV。** MAME の実装は骨組みだけで、音を出さない（`sound_stream_update` が空）。
   命令は 64bit × 256 語が 2 面。逆アセンブラも「16 進で出すだけ」の仮置き。
   **命令の意味は誰もまだ解いていない**。ROM からマイクロプログラムを取り出し、
   実機の音と突き合わせて解くことになる（MEG のときと同じ進め方）

1 が無いと 2 も 3 も確かめようがない。
